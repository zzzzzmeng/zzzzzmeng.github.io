SGLang 与 vLLM main 实现深度对比框架

2026-08-06

状态：框架版 v0.1，尚不包含胜负结论。
基准日期：2026-08-06（Asia/Shanghai）。
目标：先穷举可比维度，随后按条目 ID 逐项做源码级分析。

1. 对比基线

本系列固定使用以下官方仓库提交，避免讨论过程中 main 漂移：

框架 官方仓库 main 基准提交 提交页

vLLM vllm-project/vllm 8c0f029ac7718af4400d7542bb99417cb901d220 8c0f029

说明：

  • 当前工作区的 SGLang HEAD 是 ae848116662ece923501131ce773a4602223237e，早于上述官方基准；本文中的远端源码链接一律固定到基准 SHA。
  • 主线分析对象是 LLM/VLM 推理和在线服务核心。图像/视频生成、SGLang 前端语言、独立网关等非对称能力单列，不强行做一一对应。
  • vLLM 以当前主路径 vllm/v1 为核心；只有当兼容层或旧路径仍被公共入口调用时，才纳入主调用链。
  • “有同名功能”不等于“语义等价”。后续结论必须说明约束、默认值、回退路径、硬件范围和失败语义。

2. 分析规则

2.1 每个条目的固定输出

后续逐项分析统一填写：

  1. 问题定义与边界。
  2. SGLang 入口、核心类/函数、完整调用链。
  3. vLLM 入口、核心类/函数、完整调用链。
  4. 核心状态、数据结构及其所有权。
  5. 正常路径、回退路径、异常与取消路径。
  6. 并发模型、同步点、CPU/GPU 通信和复杂度。
  7. 配置项、默认值、自动选择逻辑和不兼容组合。
  8. 正确性、性能、显存、可扩展性和工程权衡。
  9. 支持矩阵：模型、量化、硬件、并行模式和部署形态。
  10. 源码证据、测试证据、基准方案、结论与置信度。

2.2 证据等级

等级 含义
E0 README、文档或 CLI 声明；只能证明对外宣称
E1 注册表、配置和静态源码入口；证明代码存在
E2 调用链、状态流和回退路径闭环；证明实际实现方式
E3 单元/集成测试覆盖；证明特定输入下的行为
E4 同环境可复现实验；证明当前软硬件组合下的正确性或性能

每条结论标注 待分析 / 部分验证 / 已验证 / 不适用，并至少达到 E2；性能结论必须达到 E4。

2.3 公平性约束

  • 固定模型、权重格式、精度、上下文长度、输入/输出长度分布和随机种子。
  • 固定 GPU/CPU、驱动、CUDA/ROCm、PyTorch、通信库和容器环境。
  • 分开比较默认配置、对齐配置和各自最佳调优配置。
  • 同时报 TTFT、ITL/TPOT、E2E、吞吐、并发、P50/P95/P99、峰值显存和主机开销。
  • 区分冷启动、预热后、CUDA Graph/编译完成后和稳定高负载阶段。
  • 不把模型特化优化泛化为框架通用优势；不把暂未接入等同于架构不能支持。

5. 逐项对比清单

以下复选框只表示分析进度；初始均为待分析。

A. 产品边界与公共接口

  • A01 推理任务矩阵：生成、embedding、pooling、score、rerank、分类及其他任务。
  • A02 在线与离线 API：同步/异步引擎、批量输入、流式输出和取消接口。
  • A03 OpenAI 兼容面：Completions、Chat、Responses、Embeddings、Transcriptions 等端点及语义差异。
  • A04 非 OpenAI 协议：Anthropic、Ollama、原生 HTTP、gRPC 或其他入口。
  • A05 请求/响应数据模型：字段覆盖、默认值、校验、兼容字段与扩展字段。
  • A06 Sampling 参数：支持集合、优先级、互斥关系和默认行为。
  • A07 SGLang 前端语言与运行时协同；vLLM 是否存在等价编程抽象。
  • A08 会话、多轮状态、prompt fork 和服务端状态管理。
  • A09 插件体系：模型、平台、输入处理、解析器、算子和外部存储的扩展边界。
  • A10 配置体系：CLI、Python、环境变量、配置文件的覆盖顺序和派生逻辑。
  • A11 向后兼容与弃用策略：API、配置、序列化协议和旧引擎路径。
  • A12 服务网关范围：单引擎、多副本路由、模型路由、限流和服务发现是否属于项目本体。

B. 总体架构与进程拓扑

  • B01 控制面与数据面的边界、状态所有权及生命周期。
  • B02 API server、tokenizer、scheduler、detokenizer、worker 的进程/线程拓扑。
  • B03 Engine core 的同步与异步架构，以及前后台事件循环。
  • B04 进程间通信：队列、共享内存、ZeroMQ、RPC/gRPC、序列化和复制次数。
  • B05 单 GPU、单机多 GPU、多机和多副本时拓扑如何变化。
  • B06 Data-parallel controller、负载路由和 engine rank 管理。
  • B07 tokenizer 放置、并行 tokenization 和 detokenization 放置。
  • B08 调度与执行重叠：CPU 调度、GPU forward、采样、输出回传的流水化。
  • B09 启动阶段：配置解析、模型探测、显存 profiling、进程拉起、warmup 和 graph capture。
  • B10 停止阶段：排空、取消、子进程回收、通信组销毁和资源泄漏防护。
  • B11 Python、C++、CUDA、Rust 组件的职责边界和 ABI/API 稳定性。
  • B12 核心对象状态机：请求、批次、worker、engine 和连接器的状态迁移。
  • B13 多租户或多模型是否共享进程、GPU、cache 与控制面。
  • B14 故障域：API、scheduler、worker、远端 KV、网关故障分别影响哪些请求。

C. 请求预处理与输出链路

  • C01 模型与 tokenizer 配置探测、trust_remote_code 和 revision 处理。
  • C02 chat template 选择、覆盖、内容格式与消息规范化。
  • C03 文本 tokenization：批量化、异步化、缓存和超长输入处理。
  • C04 直接 token IDs、prompt embeddings、encoder inputs 等非文本输入通路。
  • C05 多模态占位符展开、processor 调用、输入哈希和 feature 对齐。
  • C06 参数校验时机：API 层、engine 层、scheduler 层和 model runner 层。
  • C07 请求 ID、trace context、租户、优先级、deadline 和自定义 header 的传播。
  • C08 prefix cache key：token、adapter、多模态输入、模型配置和 salt 的组成。
  • C09 请求入队、背压、排队上限、拒绝策略和 admission control。
  • C10 客户端断开、显式 abort、timeout 后的取消传播与 KV 回收。
  • C11 streaming：chunk 粒度、首包、增量 detokenization、Unicode 边界和 SSE 行为。
  • C12 logprobs、prompt logprobs、top-k logprobs 和 token rank 的计算位置。
  • C13 stop token/string、bad words、min tokens 和终止原因的一致性。
  • C14 usage 统计：prompt/cache/generated/speculative token 的口径与流式上报。
  • C15 批量请求部分失败、重试和顺序保持语义。

D. 调度与连续批处理

  • D01 scheduler 核心数据结构、一次 step 的输入输出和时间复杂度。
  • D02 continuous batching 的请求加入/退出时机。
  • D03 prefill 与 decode 混批策略及资源竞争。
  • D04 chunked prefill 的切分规则、token budget、阈值和默认启用条件。
  • D05 长 prompt 与短请求的公平性、head-of-line blocking 和 starvation 防护。
  • D06 FCFS、优先级、deadline、SLO 或自定义策略的实现与稳定性。
  • D07 GPU token budget、sequence budget、encoder budget 和显存预算的协同。
  • D08 preemption：recompute、swap、暂停/恢复及被抢占请求的状态保存。
  • D09 prefix-aware 调度：cache 命中是否影响选择、排序和跨 worker 路由。
  • D10 async scheduling/overlap scheduling 的滞后一拍状态、收益和限制。
  • D11 batch invariant 操作、确定性以及批次形状变化的影响。
  • D12 CUDA Graph bucket 与调度 batch shape 的协同。
  • D13 sliding-window、Mamba/SSM、hybrid model 的 cache budget 调度。
  • D14 多模态 encoder 调度、encoder cache 命中和输入预算。
  • D15 structured output grammar 尚未编译完成时的阻塞/跳过策略。
  • D16 speculative decoding 的 draft token budget、verify 长度和调度整合。
  • D17 pipeline parallel 的 microbatch 划分、bubble 和输出排序。
  • D18 data-parallel rank 选择、负载估计、sticky routing 和迁移。
  • D19 Prefill/Decode 解耦模式下的准入、bootstrap 和 KV 就绪协调。
  • D20 调度开销剖析：Python 对象、锁、队列、批处理 metadata 和 CPU 瓶颈。

E. KV Cache 与内存系统

  • E01 基本抽象：page/block、token slot、layer spec、cache group 和请求映射。
  • E02 PagedAttention block table 与 radix tree/prefix tree 的核心差异。
  • E03 prefix cache 的插入、匹配、引用计数、锁定与释放生命周期。
  • E04 block/page size 对碎片、kernel、命中率和调度粒度的影响。
  • E05 物理分配器、空闲表、连续性要求、对齐和碎片整理。
  • E06 淘汰策略：LRU、优先级、树节点粒度、可驱逐条件和开销。
  • E07 cache hash：哈希算法、碰撞处理、跨进程稳定性与安全 salt。
  • E08 full attention、sliding window、local attention、Mamba/SSM 的混合 cache。
  • E09 MLA 的 latent KV 布局、吸收路径和普通 MHA/GQA 布局差异。
  • E10 KV dtype：FP16/BF16/FP8/其他低精度的元数据、scale 和 kernel 约束。
  • E11 KV 初始化时的显存 profiling、可用块数计算和冗余预留。
  • E12 host CPU offload、pinned memory、异步拷贝和带宽隐藏。
  • E13 多级/分层缓存：GPU、CPU、NVMe、远端存储的索引与一致性。
  • E14 外部 KV connector/store 的接口、插件注册和能力协商。
  • E15 跨实例 KV 传输的数据布局、metadata、zero-copy/RDMA 和完成通知。
  • E16 session cache、prompt fork、共享前缀和 copy-on-write 语义。
  • E17 cache flush、模型/adapter 更新后的失效规则和竞态处理。
  • E18 VMM/虚拟内存、稀疏 KV、压缩 KV 或其他实验性内存机制。
  • E19 多模态 processor/encoder cache 与文本 KV cache 的边界。
  • E20 cache 观测：使用率、命中率、驱逐、等待、传输和逐请求事件。

6. 建议的深入讨论顺序

为了先建立主干认知，建议按以下顺序推进：

  1. B02 → B03 → B04 → C09 → D01：画出完整请求与进程调用链。
  2. D03 → D04 → D08 → D10 → D20：比较调度器的核心设计。
  3. E01 → E02 → E03 → E06 → E13：比较 Paged KV 与 Radix/Prefix Cache。
  4. F02 → F06 → F07 → F11：比较执行器、CUDA Graph、编译与采样。
  5. G01 → G03 → G05 → G06：比较 attention 抽象和关键 kernel ABI。
  6. J01 → J04 → J10 → J12：比较并行、MoE 通信和负载均衡。
  7. 再按需求进入 K/L/M/O/P/Q 等专项。
  8. 最后用 S09–S18 建立可复现基准，验证前面得到的实现判断。

如果更关注线上选型，可以改用：A → R → O → S → D/E/F。如果更关注内核学习，可以改用：F → G → I → J → E/D。
